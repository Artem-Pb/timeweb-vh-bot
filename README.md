# Бот для работы с API Timeweb Hosting

Простой Telegram-бот, который обращается к API Timeweb Hosting и предоставляет данные из аккаунта пользователя по запросу:

- баланс;
- список доменов;
- список сайтов.

## Требования

- Python 3.10
- aiogram 3.31.0
- aiohttp 3.14.3
- и т. д.

Полный список зависимостей указан в файле [requirements.txt](requirements.txt).

## Установка

```bash
git clone git@github.com:Artem-Pb/timeweb-vh-bot.git
cd timeweb-vh-bot
python3.10 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Настройка окружения

Переменные в файле `.env.example` представлены без значений. Перед запуском необходимо создать файл `.env`, перенести в него переменные из `.env.example` и заполнить их нужными значениями.

| Переменная   | Способ получения |
| ------------ | ---------------- |
| `BOT_TOKEN`  | Перейти в [BotFather](https://t.me/BotFather), создать бота и получить его токен вида `1234567890:AAEExampleFakeTokenNotReal12345` |
| `TW_API_KEY` | Получить ключ через поддержку [Timeweb.Hosting](https://hosting.timeweb.ru/support/help/other-question). Ключ имеет вид: `a1B2c3D4e5F6g7H8i9J0k1L2m3N4o5P6` |
| `TOKEN`      | Получить с помощью [API-запроса](#получение-token), используя `TW_API_KEY`, логин и пароль аккаунта [Timeweb.Hosting](https://hosting.timeweb.ru/login). ключ имеет вид: `a1b2c3d4-11111111111111-e5f6a7b8c9d0` |
| `LOGIN`      | Логин аккаунта Timeweb.Hosting, к которому подключается бот |
| `PROXY_URL`  | Необязательно. SOCKS5-прокси для запросов к Telegram Bot API вида `socks5://user:password@host:port`. Нужен только если Telegram блокируется на уровне хостинга/региона (обнаруживается по таймауту на этапе TCP-подключения к `api.telegram.org:443`); если переменная не задана, бот подключается напрямую |

### Получение TOKEN

```bash
curl -X POST "https://api.timeweb.ru/v1.2/access" \
  -H "accept: application/json" \
  -H "x-app-key: TW_API_KEY" \
  -u {login}:{password}
````

## Запуск

Перед первым запуском полезно проверить, что окружение настроено верно (все переменные `.env` на месте, Telegram и Timeweb API доступны) — скрипт [`check_env.py`](check_env.py):

```bash
source .venv/bin/activate
python check_env.py
python main.py
````

## Деплой

Инструкция для запуска на shared/VPS-хостинге по SSH, без root и без `systemd` (актуально, например, для тарифов Timeweb ВХ).

### Подготовка сервера

```bash
git clone https://github.com/Artem-Pb/timeweb-vh-bot.git
cd timeweb-vh-bot
python3.10 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Если `ensurepip` недоступен (нет root для `apt install python3.10-venv`) — создать venv флагом `python3.10 -m venv --without-pip .venv`, поставить `pip` вручную через [get-pip.py](https://bootstrap.pypa.io/get-pip.py), дальше работать через `.venv/bin/python3 -m pip ...` вместо `pip ...`.

### `.env` на сервере

Создать `.env` так же, как описано в разделе ["Настройка окружения"](#настройка-окружения) выше, и выставить права только владельцу:

```bash
chmod 600 .env
```

### Проверка окружения

```bash
.venv/bin/python3 check_env.py
```

Скрипт проверяет версию Python, заполненность обязательных переменных `.env`, доступность Telegram Bot API (напрямую или через `PROXY_URL`, если он задан) и доступность Timeweb API с реальной авторизацией. Смотреть на `FAIL` в выводе — это конкретная причина, которая помешает боту запуститься.

### Если Telegram недоступен напрямую с сервера

Часть хостингов не имеет прямого доступа к `api.telegram.org` — `check_env.py` покажет `FAIL` на проверке Telegram Bot API с таймаутом на этапе TCP-подключения (можно перепроверить вручную: `curl -v --max-time 10 https://api.telegram.org`).

В этом случае — поднять SOCKS5-прокси (например, [microsocks](https://github.com/rofl0r/microsocks)) на сервере, откуда есть доступ к Telegram, и указать его в `.env` через `PROXY_URL` (см. таблицу переменных выше). Некоторые хостинги дополнительно пропускают наружу только стандартные веб-порты — если прокси на нестандартном порту (например, `1080`) тоже не проходит, стоит поднять его на порту `80`. После смены `PROXY_URL` перезапусти `check_env.py`, пока не увидишь `OK` на всех строках.

### Запуск с автоперезапуском

Когда `check_env.py` показывает `OK` по всем пунктам — процесс должен переживать закрытие SSH-сессии и перезапускаться при падении:

```bash
nohup bash -c 'while true; do .venv/bin/python3 main.py; sleep 5; done' > autostart.log 2>&1 &
disown
```

Проверка, что процесс поднялся:

```bash
ps aux | grep main.py
cat autostart.log
```

Финальная проверка — закрыть SSH-сессию, открыть новую и убедиться, что бот всё ещё отвечает в Telegram.

## Проверим, что бот работает

Перейти в [BotFather](https://t.me/BotFather), узнать `@name_bot`, найти бота и запустить его командой `/start`.

Можно также пройтись по всем кнопкам бота и проверить их работу.

Бот работает через long polling, без использования webhook. Время ответа зависит от текущей доступности Telegram и качества соединения с ним в регионе.


## Структура проекта

Проект разделён на отдельные файлы по назначению:

* `main.py` — точка входа и запуск бота через polling.
* `handlers.py` — обработчики команд, сообщений и действий пользователя.
* `service.py` — взаимодействие с API Timeweb.Hosting.
* `keybords.py` — клавиатуры и кнопки Telegram-бота.
* `config.py` — загрузка и хранение конфигурации из `.env`.
* `texts.py` — тексты сообщений бота.
* `exeptions.py` — пользовательские исключения и обработка ошибок.
* `check_env.py` — самостоятельная проверка готовности окружения перед запуском (см. разделы "Запуск"/"Деплой").

Такое разделение позволяет отдельно изменять интерфейс бота, тексты, работу с API и настройки, не смешивая их между собой.

## Логирование

Логи записываются одновременно в `bot.log` и выводятся в консоль — удобно для дебага в процессе разработки. При деплое через автозапуск (см. раздел «Деплой») консольный вывод дополнительно перехватывается в `autostart.log` за счёт перенаправления `> autostart.log 2>&1`.

При возникновении проблем в первую очередь стоит посмотреть последние записи в `bot.log` или вывод в консоли. Особое внимание стоит обратить на сообщения об ошибках, исключения и ошибки при обращении к API.

При передаче логов для диагностики удалите из них токены, пароли, API-ключи и другие чувствительные данные.
